# RoboCOIN v4：动作与 EEF 交付核验

## 转换规则

| 项目 | 规则 |
|---|---|
| state | 当前观测映射，左右臂关节 rad 为必备表示；不由 action 累加 |
| 发布 action | 默认原行保留，仅做确认过的单位、顺序、方向转换；不默认它是下一帧实测状态 |
| 同帧复制 | 对整集检查：至少 3 行、有关节/夹爪运动；所有已映射字段和共享具名原始分量严格相等，映射和 mask 一致。满足才派生 state[t+1]；否则保留发布 action |
| 派生末帧 | 没有下一状态，全部 action 值和 mask 置 0 |
| 动作来源 | 每行 `action_source_kind`：0 保留发布 action，1 派生下一状态；`action_target_step`：派生非末帧为 1，其余为 0。逐集原因见 `meta/episodes.jsonl` 的 `action_semantics` |
| 夹爪 | 保留原值，越大越开；不假设 0～1，不裁剪。灵巧手夹爪槽留空，完整手指原始列透传 |
| EEF | 明确 SDK xyz+xyzw 成套映射并保留原生 frame；其他已确认 xyz 单独填入，未确认 Euler 旋转保留原列、旋转 mask=0 |
| 四元数 | 有限且范数 >1e-8 即可归一化，不要求范数偏差 ≤1%；连续性检查拒绝孤立 >120° 双向跳变且前后 <30° 的中间帧，原值保留、不插值造值 |
| 时间 | 下一状态跨度可由 sample_dt 读取；发布网格仍不是经过证实的物理采样时钟，不伪造有效 action_dt/source_dt |

判定“同帧复制”是透明且可复现的转换规则，不能证明作者的数据生成历史。静止片段不能据数值相等判成复制。`source_native` 表示保留发布值，作者仍可能已经做过派生。原生控制目标和下一帧实测位置并不完全等价，训练可按来源选择。

四元数孤立跳变门限是保守启发式，不是作者或机器人硬件的运动限制。有限非零也不保证物理姿态必然准确；没有外部真值时只恢复表示明确、未触发上述异常的值。位置有效性独立于旋转。

## 验证范围与结果

- 全部 809 仓库的元数据通过 26 种结构映射检查。
- 809 仓库首尾 1,618 集、1,153,566 行数值样例：779 集派生下一状态，839 集保留发布 action。正式机逐集重新判断，不按样例结果覆盖整库。
- 117,844 组 SDK 四元数中，117,688 组可用；恢复 3,172 组被旧 1% 门限屏蔽的旋转；156 组孤立大角度跳变仍屏蔽。
- 29 个代表仓库、58 集、29,064 行完成实际转换、逐值/逐 mask 检查、原始列无损核对、视频压缩包序列哈希及 RGB 检查。
- 29 个输出均通过真实 LeRobot 0.5.0 加载。沿用独立加载包的薄兼容子类；不声称未经适配的原生类直接通过。
- 29 个输出断点重跑均为 skipped_verified，未重复转换。
- 定向测试覆盖：动态复制、静止歧义、已是下一状态、真实闭合命令、单行细微差异、短集、同仓库混合集；四元数重排、非单位恢复、近零/非有限值、孤立跳变、旋转无效但 xyz 保留。

机器可读结果：`reports/acceptance_semantics_v4.json`、`numeric_semantics_v4.json`、`verification_semantics_v4.json`、`official_load_semantics_v4.json`。29 仅进行了样例转换，不是 809 仓库的全量生产验收。

## 两个 AgiBot 仓库的时序复查

本轮只补齐两个仓库的数值文件，没有下载其全部视频。发布元数据集数、总行数和实际读取结果一致。

| 仓库 | 核查集数 / 行数 | 右夹爪同帧负相关集数 | 最佳正相关偏移范围 | 最佳相关系数中位数 |
|---|---:|---:|---:|---:|
| AgiBot-g1_box_storage_c | 39 / 23,361 | 34 | 21～80 帧 | 0.704 |
| AgiBot-g1_picks_up_cardboard_box | 277 / 149,409 | 33 | 25～82 帧 | 0.969 |

偏移搜索为 −120～120 帧，并至少保留 60% 重叠区间；正偏移表示拿当前 action 与后面的 state 比较。常量夹爪轨迹没有可解释的相关系数，不计入最佳偏移统计。

结论：这些数据不能按同帧负相关认定夹爪反向；也不支持统一移某个固定帧数。闭合命令脉冲、观测响应和再次张开叠加，能造成当前行 action 已张开而 state 仍在收拢。仅凭发布的 30 fps 时间网格，无法区分机械响应、遥操作链路、记录对齐或作者重采样各自的影响，不能把“最佳相关偏移”当作真实通信延迟。

处理：保留作者发布 action，不反转、不自动时移；逐集诊断见 `reports/agibot_timing_v4.json`，训练可按该报告单独评估或筛选。这是已记录的时序不确定性，并非已恢复出的物理对齐关系。

作者方向依据：[PR #7 字段说明](https://github.com/FlagOpen/RoboCOIN/pull/7/files)。当前公开记录代码将观测和发送动作放入同一记录行：[record.py](https://github.com/FlagOpen/RoboCOIN/blob/b3261fe7cf92d18d9f8545c4b8ad9813dd1d2edd/src/lerobot/record.py#L250)；它不能证明这批历史发布文件完整使用了该链路。
